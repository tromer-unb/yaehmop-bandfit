# Troubleshooting

| Symptom | Likely cause / remedy |
|---|---|
| `No module named ase/numpy/PIL/scipy/yaml` | Activate the cloned repo `.venv` and install `pip install -r requirements.txt`. |
| `YAeHMOP bind not found` | `--prepare-only` does not require it; actual solver requires separately installed `bind`, exported `YAEHMOP_BIND` and `YAEHMOP_PARAM_FILE`. |
| CSV says `header must be exactly` | Use `x,band_1,band_2[,band_3,...]` without extra columns and sort energies at each x. Saved EHT `orbital_*` fixtures are for the plotter, not input references. |
| No PBE bands appear | This repository intentionally does not redistribute third-party ab initio reference files. The carbon samples contain saved physical **EHT** eigenvalues. |
| `Invalid or out-of-range plot box` | `--bbox L,T,R,B` must be within the **oriented** normalized raster pixels. Use `inspect_png.py` to inspect suggested bounds. |
| `N reliable curve colors were not found` | Supply distinct `--colors` or use exact CSV/manual annotations. Do not invent missing bands. |
| `Not a verified P5 bitplane` | A normal gray PNG is not the 8-bit layer format. Use `--mode colors`, `mono`, `auto` or numeric CSV. |
| `Invalid band gap` | The gapped semiconductor interface does not accept gapless Dirac/metal cases; use the separately designed carbon protocol. |
| `metallic reference` / `No positive gap` with a DFT folder of a metal | Use `objective = metal` (bands aligned at E_F) and set `fermi = …` in `[reference]` to the Fermi level of the SCF run; see `docs/DFT_REFERENCE.md` (Metals). |
| `overlap S(k) not positive definite` (warning in the export, or many `overlap` rejections in `history.csv`) | The basis is nearly linearly dependent, usually very diffuse added shells (small ζ). The fitter rejects such candidates (`overlap_min_eig` in `[fit]`, default 10⁻³), so new fits always export H(R), S(R); for an old parameter set, refit, drop the extra shell, or raise the lower ζ bound. |
| `Invalid raster / multipage` | Export **one** still raster frame in 8-bit RGB; animated GIF and multipage TIFF have ambiguous scientific meaning. |
| Diamond/graphite are treated as 2D | Set `dimension = 3` in `[band_path]`. Fitting and recomputation now both write `Lattice 3` with the same overlap radius. Fits made before this fix were optimized as a 2D slab (`Lattice 2`, images `5 5 0`) even with `dimension = 3`; `--from-fit` warns about such `fit.json` files and they must be refitted. |
| A fit is slow | Use `overlap_radius = auto` (`[fit]`, `--overlap-radius auto`): bulk phases usually converge with radius 3–4 instead of 5. Population optimizers (`cmaes`, `differential-evolution`, `genetic`, `bayesian`) use `--parallel` candidates at once (default CPUs / systems); run one fit at a time with all cores rather than several fits sharing them. `--optimizer alternating` helps most for 3D systems with expensive lattice sums; for 2D slabs `cmaes` is usually better. The final polish (25 % of the budget) runs its starting points (up to 4) at the same time. |
| `FAST_HAMILTONIAN disabled` | The numpy H(k) did not reproduce `bind` (e.g. an original YAeHMOP with K hardwired in THIN mode); the `alternating` optimizer then runs its fast stages with normal YAeHMOP calls. Use the bind of github.com/ac-dias/yaehmop. |
| `WARNING ...: with the fitted table, radius r differs from radius 5` | The fitted orbitals are more diffuse than those tested before the fit (`overlap_radius = auto`). The export is consistent (same radius), but refit with a larger `overlap_radius` for converged lattice sums. |
| `spin_combine.py`: native moment differs from DFT | The two channel tables are fitted separately; by default they are aligned before the native `--common-fermi` run (`alignment` in `fit_summary.json`). The remaining difference (Fe: 2.14 vs 2.24 μB) comes from the uniform Hii shift, which is not rigid in EHT. Refit both channels together with `spin_joint_fit.py` (one energy zero; Fe: 2.23 μB). Also, the native run counts states at T = 0 on a small mesh (default 9³): its moment moves in steps of 1/N_k. |
| `spin_joint_fit.py` never improves on the start | Near a good fit the `metal` objective has narrow valleys (the local-extrema term jumps when an EHT extremum disappears). Keep the small CMA-ES step of a refinement (`--sigma0 0.02`, the default with `--start-up/--start-down`) or use `--optimizer nelder-mead`. |
| GitHub Actions are slow or use too much compute | Actions deliberately run lightweight source+I/O tests only; full physical fitting must be performed locally by users. |

If an image trace is visibly wrong, stop and investigate `extraction_qa.json` and the preview rather than feeding it to the solver. Attach a minimal synthetic or openly licensed reproducer and full error text when opening an issue. Do not upload proprietary/third-party DFT data without permission.
